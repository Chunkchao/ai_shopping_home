# UI Contract: 公司官网首页

## 1. 页面路由契约

- Route: /
- Purpose: 官网首页（品牌展示 + 品类入口 + 联系转化）
- Inputs: 无必填 URL 参数
- Outputs: 渲染由 Mock 数据驱动的首页内容模块

## 2. 区块可见性契约

- hero: 必显（允许媒体降级为占位图）。
- categories: 必显（最少 3 项；不足时显示占位卡片）。
- brandStory: 建议显示（可通过配置关闭）。
- contact: 必显（至少一种可用联系方式）。

## 3. 交互契约

- 导航点击:
  - anchor 类型: 平滑滚动到目标区块。
  - route 类型: 进入指定路由。
  - external 类型: 新窗口打开并保留来源上下文。
- 主 CTA 点击:
  - 跳转到品牌介绍区块或详情承接页。
- 品类卡片点击:
  - 进入对应详情承接页或锚点区块。

## 4. 状态反馈契约

- Loading: 显示骨架屏或占位块，不阻塞导航可见。
- Empty: 显示“暂无内容”空态文案和返回首页主入口。
- Error: 显示错误提示与“重试”动作，保留联系信息可见。
- Ready: 所有关键模块可交互。

## 5. 体验一致性契约

- 术语一致:
  - 所有按钮文案使用统一动词风格（如“了解更多”“立即咨询”）。
- 视觉一致:
  - 间距、字号、色彩从 tokens.css 读取；禁止局部硬编码主题色。
- 响应式一致:
  - 桌面端与移动端保持信息层级一致，允许布局重排但不丢失关键内容。

## 6. 性能契约

- 首屏关键内容（标题、品牌短句、主 CTA）在 3 秒内可见。
- 导航交互反馈在 300 毫秒内出现（高亮、滚动开始或页面跳转）。
- 首页 LCP <= 2.5 秒（常见网络条件）。

## 7. 验收证据契约

- 自动化测试报告:
  - 用户故事路径测试通过。
  - Mock 数据异常场景测试通过。
- 视觉证据:
  - 桌面和移动端关键区块截图。
- 性能证据:
  - Lighthouse 或等效报告截图/数据。
